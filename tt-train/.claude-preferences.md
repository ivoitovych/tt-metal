# Claude Code Preferences for tt-train

## Git Workflow

### Branch Naming Convention
When working on features, use consecutive numbered branches:
- Pattern: `ivoitovych/<feature-name>-<number>`
- Example: `ivoitovych/bert-model-for-ttml-layernorm-configurable-epsilon4`

### Amendment Safety Protocol
**IMPORTANT**: When amending a commit, ALWAYS create a new consecutive branch number.

**Why**: This preserves the previous state and prevents accidental data loss.

**Process**:
1. Make changes/improvements
2. Create NEW branch with next consecutive number (e.g., epsilon4 → epsilon5)
3. Amend commit on the NEW branch
4. Push the NEW branch (no force push needed since it's a new branch)

**Example**:
```bash
# Current branch: epsilon4 (has state A)
# After making changes:
git checkout -b ivoitovych/bert-model-for-ttml-layernorm-configurable-epsilon5
# IMPORTANT: Check what files will be added
git status
# Add files consciously (not git add -A)
git add path/to/file1.cpp path/to/file2.hpp
git commit --amend -m "..."
git push myfork -u ivoitovych/bert-model-for-ttml-layernorm-configurable-epsilon5
```

**Result**: epsilon4 stays frozen with state A, epsilon5 has new state B

### Never Use Force Push for Amendments
- ❌ NEVER: `git push -f` after amending
- ✅ ALWAYS: Create new branch number and push normally with `-u`

### CRITICAL: Always Check Git Status Before Adding Files
**IMPORTANT**: Before running `git add`, ALWAYS check `git status` first to see what files will be added.

**Why**: Using `git add -A` or `git add .` blindly can include development artifacts (like CLAUDE.md, .claude-preferences.md) in production branches.

**Process**:
1. Make changes to code
2. Run `git status` to see ALL modified/untracked files
3. Add files CONSCIOUSLY by specifying exact paths
4. Verify with `git status` again before committing

**Example - Correct Workflow**:
```bash
# Step 1: Check what changed
git status

# Step 2: Review the list carefully
# Look for development artifacts:
#   - CLAUDE.md (development notes)
#   - .claude-preferences.md (workflow documentation)
#   - *.swp, .DS_Store, etc. (editor artifacts)

# Step 3: Add only production files explicitly
git add sources/ttml/modules/layer_norm_module.cpp
git add sources/ttml/modules/layer_norm_module.hpp
git add tests/modules/layer_norm_epsilon_test.cpp
# ... add other production files one by one

# Step 4: Verify staging area is clean
git status

# Step 5: Commit only if clean
git commit -m "..."
```

**Example - What NOT to Do**:
```bash
# ❌ NEVER do this blindly:
git add -A        # Adds EVERYTHING including development artifacts
git add .         # Same problem

# ✅ ALWAYS do this:
git status        # Check first
git add file1 file2 file3  # Add consciously
git status        # Verify before commit
```

**Production vs Development Files**:
- Production files: Source code, tests, configs, build files
- Development artifacts: CLAUDE.md, .claude-preferences.md, editor temp files, notes

## Commit Message Format
- No AI attribution or references
- Focus on technical details and changes
- Include test results and validation
