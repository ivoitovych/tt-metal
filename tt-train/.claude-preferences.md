# Claude Code Preferences for tt-train

## Git Workflow

### Branch Naming Convention
When working on features, use consecutive numbered branches:
- Pattern: `ivoitovych/<feature-name>-<number>`
- Example: `ivoitovych/bert-model-for-ttml-layernorm-configurable-epsilon4`

### Amendment Safety Protocol
**IMPORTANT**: When amending a commit, ALWAYS create a new consecutive branch number.

**Why**: This preserves the previous state and prevents accidental data loss.

**Process**:
1. Make changes/improvements
2. Create NEW branch with next consecutive number (e.g., epsilon4 → epsilon5)
3. Amend commit on the NEW branch
4. Push the NEW branch (no force push needed since it's a new branch)

**Example**:
```bash
# Current branch: epsilon4 (has state A)
# After making changes:
git checkout -b ivoitovych/bert-model-for-ttml-layernorm-configurable-epsilon5
git add -A
git commit --amend -m "..."
git push myfork -u ivoitovych/bert-model-for-ttml-layernorm-configurable-epsilon5
```

**Result**: epsilon4 stays frozen with state A, epsilon5 has new state B

### Never Use Force Push for Amendments
- ❌ NEVER: `git push -f` after amending
- ✅ ALWAYS: Create new branch number and push normally with `-u`

## Commit Message Format
- No AI attribution or references
- Focus on technical details and changes
- Include test results and validation
